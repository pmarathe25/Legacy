# autonomous production

Opted-in people attempt their authored recipe when living, local, fed enough, and free of other work. A granted start consumes one setup interval; work progresses on later ticks. Multi-input claims use deterministic conservative per-good prefixes: rejected claims still occupy priority for the interval, so some usable stock can be deferred. IDs come from a saved monotonic allocator. Inputs are reserved from pre-tick stock and cannot use outputs produced in the same interval.

`opportunities` exposes individually eligible work before stock quantities are awarded, so contention does not erase other people's intentions. It does not reserve goods, choose among other activities, or guarantee access to a site or tools; the composing host must still resolve those constraints and physical admission. The interval host does not yet include these work opportunities in its common personal-choice round.

The ignored `concentrated_work_opportunity_benchmark` checks the same 100,000 intentions across worker counts with one shared stock. On one development machine its median proposal times were 6.58, 4.01, 2.37 and 1.85 ms with one, two, four and six workers. This measures proposal generation, not complete work admission or whole-simulation scaling.

A person's policy may set `disregard_claims` to attempt physical work with claimed goods. A work-request recipient can make the same choice through their own preference. The fused runtime records actual unauthorized input use only after a reservation succeeds; a present claimant's directed trust can change, while an absent claimant gains no direct observation. Other people's claims and permissions remain unchanged.
