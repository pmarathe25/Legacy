# game-world

`game-world` provides a generic host over one shared component store. `GenericHost<State, Event, Storage>` owns logical time, checked identity and event counters, typed records, and snapshots. Composition supplies the schema, typed state and events, contextual validation, and systems. An application storage wrapper implements the two-method `StorageAccess` interface; it retains the same single Store.

State and storage are separate fields for disjoint borrowing. `parts_mut()` also lends the existing event records without cloning them. `append_many` advances event sequence only; `bump_revision` publishes a caller revision, while `publish_many` advances both. Callers preflight the complete transaction budget before owner writes.

`ReadSet` records selected present or absent typed rows, entity presence, and scoped membership. Binding it to a batch admits an owner-bound `ReadGuard` over those opening facts, the admitted typed projections, and the exact writes; unrelated component edits do not invalidate a projection. `Transaction` combines one `Batch`, owner-bound `ReadGuard`s, allocation count, typed events, final logical time, and an explicit revision budget. Capture `transaction_opening()` before preparation; its opaque lineage prevents reuse across separate hosts, clones, or restores. `commit_transaction` rejects changed opening cursors or backwards time, preflights identity, event, and revision arithmetic, validates all guards, and checks identity reservations before applying the schema-validated batch. It then advances time and counters and publishes records as one admitted transaction. New entities must lie in the reserved ID interval. Rejected admission preserves component rows, counters, events, revisions, and runtime state. Owners validate their private metadata before host admission and finalize precomputed metadata infallibly after success.

`preview` and `preview_with_tail` build transient hosts from caller-selected storage and state at an existing logical opening. Each has independent affinity; the latter copies only the supplied pending event suffix. `events_since(cursor)` borrows records whose sequence exceeds the consumed cursor, including in a retained suffix. Previews produce candidate effects for source-side admission; complete saves come from the canonical host.

The playable `game-assembly` uses this host for live storage and generic counters. The host depends only on core types, the private ECS adapter, and the simulation engine. AssemblyState retains feature runtime metadata and application coordination; canonical per-entity rows live in the shared Store. Assembly stages world intervals before publishing their combined component batch and final logical time through this transaction boundary. Some assembly policies and event reactions are still being moved into feature owners.
