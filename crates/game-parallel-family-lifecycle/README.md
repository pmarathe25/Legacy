# Columnar lifecycle staging
Reusable identity-owned committed/scratch lifecycle columns with immutable pedigree/genome metadata. Matching and conception preserve reference tick priorities; births append canonical identities only on commit. Draft generation checks protect rollback and discarded preparations. Family member objects are materialized only on export.

Lifecycle receipts use immutable fixed-size rows from `game-parallel-family-receipts`.
Only snapshot export expands strings and participant vectors. Imported arbitrary
receipts remain byte-for-byte equivalent in value and order until the first
successful commit; failed preparation leaves them intact. Retained compact frames
remain valid after later preparation, publication, and runtime destruction.

Fused lineage reads committed ruler survival and the first canonical newborn ID;
newborn enrollment consumes identities directly. Neither consumer reconstructs
family members or heap-bearing event receipts each tick.
