# Tactical geometry

Deterministic, serializable fixed-point local maps and checked movement/line-of-sight geometry. The map is persistent world state: later damage or edits change the stored obstacles, and loading does not regenerate a site. Coordinates are integer subunits rather than tiles; no renderer is required.

`content/parallel/tactics.toml` supplies a persistent local map for an authored encounter. In the administrative CLI, `tactical-fight ID REGION A B AX AY BX BY` starts a battle with explicit placements; `tactical-move ID PERSON X Y` submits one movement for the current round. `combat-order` selects attack, defense, or retreat. The ruler-bound player mode can move or order only the current ruler once an encounter exists.
Map primitives and generation are owned by [game-parallel-tactical-map](../game-parallel-tactical-map/README.md) and reexported here without save-schema changes. The runtime index stores actor geometry in identity order with direct lookup for dense IDs and binary search for sparse IDs. Movement changes cached points only after the whole batch validates; evaluated round receipts are independent. Casualties leave tombstones in the geometry array and invalidate only affected placement-slot caches. New encounters rebuild the index; old maps remain stored after battle resolution.

`examples/movement.rs` measures owner command cost and the first command after casualty compaction. `cargo run --release -p game-parallel-fused-physical --example fused_benchmarks -- fused_tactical_moves` measures command plus full next-round staging/publication, reporting initial index warmup separately. Large batches use parallel validation and actor-owned updates; request/destination hashing and occupancy reconstruction remain partial serial costs.
