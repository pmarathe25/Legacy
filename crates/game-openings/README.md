# game-openings

Binds generated starts and optional, explicitly labeled fixtures through feature-owned requests. `generated` reads `game-worldgen` settings, installs only physical and individual initial conditions, enables `game-communities`, and runs live history before assigning player control. The saved opening records the seed, settings, initial definition, source stamps, and actual handoff time. Authored scenarios retain their explicit initial arrangements. No complete campaign is implied.

**Interface:** [Source](src/lib.rs) defines the public types and operations. Hosted features register their state and request handlers through `plugin`. The public player API is bound by `game-assembly`; internal construction requests are privileged.

**Verification:** Run `cargo test -p game-openings`. Tests belong to the crate and compose required owners without the application, except for client and application integration tests.

**Content:** [Store format and extension guide](../../content/README.md). Definitions are read from files at startup and resolved snapshots survive save/load. The schema and validation live in this crate.
