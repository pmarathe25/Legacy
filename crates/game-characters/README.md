# game-characters

Characters have dispositions, relationships, aspirations, and remembered information. They rank available choices using their own knowledge and experience. Companionship, family plans, instruction, practice, and learned values can shape later decisions.

The crate owns personal judgments, plans, retries, learning, and social development. Other features supply factual opportunities and physical risk. Characters constructs motives, interprets effort and uncertainty, and chooses among them. Executable actions remain opaque to its decision systems.

`Person`, `Mind<A>`, `Stocks`, and inherited temperament are plain components in the shared store. `Person` is the canonical identity, role, cargo binding and cumulative personal work evidence; derived indexes retain only its IDs. `Stocks` owns dated inventory observations; `Mind<A>` owns plans, relationships, routes, and other personal information. Small typed interfaces expose observations and prepared changes. `MemoryLearner` receives historical stock and route information while retaining newer observations, current access rights, and existing routes. Temperament interprets opaque inherited alleles and combines predispositions with bounded experience. Biological aging and reproduction belong to Lifecycle; physical command admission belongs to the respective action owner.

Prepared stock learning stages the selected native `Stocks` row in the shared batch. Its guard checks the recipient and batch identity while allowing independent changes to other actors. Historical route learning guards the affected edge and receiving mind, then finishes the admitted field change. Both preserve newer observations and current access rights. Characters also decides whether a recipient agrees to voluntary memory instruction.

`orchestration::DecisionPort<A>` binds opaque actions and other owners' factual opportunities to the production review path. `Runtime::decide_from_port` builds personal candidates and ranks them; `ObservationPort` supplies physical rows and local catalogs for dated perception. Characters joins dependent cohorts by exact point, caps attention at 64 signals, and applies learned routes, stocks, sites, and care reconciliation. Typed lived events also enter temperament through owner-selected authored learning tags. Newborn minds and remembered permission changes have prepared owner entry points.

`people::progress_inputs` reads canonical people and placement, then uses factual physical/equipment readiness to prepare stable work inputs. Evaluations retain their exact input and stage through the common read guard, so stale placement, readiness, identity, membership or overwritten results reject before publication. This cumulative metric feeds character judgment; Workshop owns recipe progress and production. Role receivers stage role/exemption changes without selecting successors.

`receivers` prepares bounded Play credit, care and comfort relationships, delivery receipts, report knowledge, and personal lesson learning for a shared batch. Tell selects local observed stock or dated personal memory, keeps the recipient's own access rights, and guards accepted and refused outcomes. Craft lessons use the teacher's personal mastery and supplied skill evidence; route lessons transmit only remembered edges. Receiving guards retain the source rows and exact admitted writes before publication.

`views` owns read-only personal navigation, baseline manual choices, nearby-person eligibility, and ordered suggestion merging. Bare-kernel navigation explicitly uses the authored fixture catalog; ordinary navigation uses personal route knowledge. The assembly supplies factual rows and binds opaque owner actions to public commands, while Lifecycle, Transport, Cargo, Workshop, Conflict, and Invocation own their stage, location, resource, tactical, and authority menu policies.
