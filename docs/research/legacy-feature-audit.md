# Old-engine feature audit and restoration

Baseline: `eba0eb991bc09dd1be2c643c3e9ddcce6a724c88`, the parent of `f5658950`, which removed the earlier simulation. Compare with the current interval host in `crates/game-economy/src/core_interval/`. The [component inventory](legacy-component-inventory.tsv) lists all 361 baseline crate directories and captures the baseline index or owner README description for 358. Same-name directories are not evidence of parity. A directory is not necessarily a user-visible feature, and its absence does not prove that a behavior is absent under another owner.

This is a restoration inventory, not a claim of complete behavioral parity. A domain is partial unless the old behavior, current host execution, content, persistence, player access and tests have all been compared. Documentation describes the baseline's claimed behavior; historical source and tests remain necessary to establish its precise limits. Specific baseline files can be read with `git show eba0eb9:crates/CRATE/README.md` or the corresponding `src/` and `tests/` files.

## Verification criteria

For each restored feature: demonstrate its owner actually runs through `CoreHost`, with data-defined configuration and observations; exercise personal refusal or noncompliance where relevant; test resource conservation and rollback, save/resume and deterministic results across worker counts. Measure independent and contested workloads separately. Do not mark the full domain complete merely because a type, catalog, or isolated helper is present. Historical institutions are descriptions of autonomous behavior and never grant authority or bind agreements by themselves.

Autonomy applies to every domain, including work, care, speech, learning, invention, relationships, cooperation and conflict. A feature may provide physical opportunities, constraints and consequences, but it must not impose decisions or compliance as a consequence of a role, agreement, encounter or institution. Personal motives, capabilities, experience, obligations, fear and circumstances may influence choices; fear and obligation need not be experienced by every person. The current fixed ordering of activities and existing per-feature policies are not proof of this requirement and require a cross-domain audit and redesign.

An optional capability model now replaces the blanket age gate for personally selected production starts. Data-defined growth and genetic vigor determine strength, and recipes have explicit physical requirements; capability is checked before admission without deciding whether the person wants the work. This is a limited slice: legacy work, agriculture and other activity paths still use age gates, and carrying does not yet reflect individual strength. An optional birth profile initializes general inclinations from a newborn's own genes, permits individually chosen meals without a caregiver owner, and initializes work readiness from the newborn's configured preference instead of the mother's flag. Other feature-specific readiness and opportunities remain separate. Work requests, takeovers, assistance, continuation and stopping each need their own personal decisions as well.

Several work and repair opportunities also use a shared maximum hunger as an eligibility gate. This is not yet a subjective choice or a demonstrated physical inability. Revalidated personal work starts, construction, local carrying, site maintenance and tool repair choices no longer use that cutoff, but legacy scheduling and many other activities still do. These need individual motivation and explicit capability or physical consequences, rather than assuming that every person refuses or is unable at the same hunger value.

An opt-in continuation preference now lets a worker stop an ordinary active job. It does not yet compare the active job against other activities in the same round, and does not cover shared work or succession.
