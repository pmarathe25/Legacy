# Workspace and content follow-ups

A read-only dependency review found 103 workspace packages, all reachable from
the CLI's declared normal or optional path dependencies. Reachability alone is
not a reason to keep or merge a crate. The active milestone is the integrated
hourly world; these changes should support it rather than replace feature work.

Potential private-module consolidations, subject to rechecking dependencies,
tests, save compatibility, and public re-exports:

- Skill, opinion, and mission model helpers into their respective owners;
  tactical map into tactics; matching into families; social pressure into social.
- Conflict receipts into packed conflict; production output into production;
  lot work into the lot runtime; economy read into an integration/view module.
- Content import and skill catalog into one content-compilation crate, with
  their responsibilities retained as separate modules.

Keep genuinely shared production, lot, and family models and coherent feature
owners separate. The whole-boundary and interval hosts also overlap, but the
remaining features must be migrated before the redundant host can be retired.

Content extensibility needs explicit work: authored capacities should not be
silently enlarged by importing recipes; saves need stable namespaced keys and
persistent mappings to compact runtime IDs; content should expose multiple
recipe outputs where the production model already supports them; genetic trait
definitions and expression should be extensible without replacing packed data
with universal dynamic maps; and durations and rates need explicit units.
Feature-owned typed requests, constraints, and events should remain the basis
for new content, without granting institutions automatic authority or making
agreements binding.

Specific integration limits to address in context: autonomous work currently
permits one recipe policy per person; imports allocate empty stock entries for
every catalog good; container capacity sums unlike raw quantities; lot identity
currently excludes both batch provenance and expiry; regional colocation is a
coarse proxy for reach; and mechanical operations require personally carried
parts. Nutrition recognizes a fixed set of six names, while authored nutrient
maps can contain others. Saves need a versioned catalog manifest and migration
contract. Animal diets and crop outputs also encode narrow archetypes, and
generated machinery currently chooses the first compatible component mapping.

Separate a person's learned recipes, preferences, and chosen activity. Physical
reach and apparatus access should use shared location semantics, not ownership
or implicit consent. Any expansion of units, inventory identity, or food types
must preserve conservation, rollback, worker determinism, and save validation.
Bounded attention and memory are deliberate scalability tools, but should not
be confused with permanent limits on what a content pack can represent.

In particular, a skill lesson is not automatically a recipe-knowledge record:
the skills owner canonicalizes some recipes into shared skill categories. A
lesson in such a category does not establish that its recipient knows every
recipe mapped to it. A future work-choice path needs to preserve which specific
recipe was actually observed or explained, and still let each person decline,
prefer other work, or fail the physical admission checks. It must not create
jobs just because knowledge was acquired.
